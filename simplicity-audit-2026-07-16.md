# SigilZero — Simplicity Audit

## Scope

Reviewed the repository’s authored implementation end to end:

- All Next.js routes, layouts, client catalogs, and error pages under `src/app/`
- All components, hooks, content loaders, schemas, filters, and utilities under `src/`
- Content-validation and normalization scripts
- Unit and Playwright tests
- Package manifest, TypeScript/Next/Vitest/Playwright/Tailwind configuration
- Git hooks and all three GitHub Actions workflows
- Content/data structure and call sites for exported functions and components

Static assets and content entries were inventoried, but binary media and generated `.next` output were not treated as implementation code. This was a read-only audit; no files were changed.

## Summary

The highest-leverage simplifications are:

1. Remove the unreachable global audio system. It is the largest fully dead implementation and currently adds client state and browser work to every page.
2. Collapse the two overlapping CI workflows into one pipeline.
3. Eliminate disabled feature scaffolding: the home mixtape flag and the three false-gated press-kit sections.
4. Make application loaders and command-line content validation consume one set of Zod schemas.
5. Remove the unused MDX/remark/rehype stack and isolated dead feature files.

The active core is otherwise appropriately built. The content loaders, Zod validation at the file boundary, static route generation, release/mixtape filtering, accessible navigation and error states, platform embeds, and link-security attributes all have clear consumers. The analytics implementation is substantial, but its privacy filtering, URL sanitization, deduplication, and GTM contract are deliberate trust-boundary controls documented in the README; they should not be cut merely for line count. Likewise, the unit and Playwright coverage around live catalog behavior is justified. The best simplification here is deletion of abandoned parallel paths, not a broad rewrite of the working catalog architecture.
